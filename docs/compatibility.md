The source repository `YASHMAHAKAL/crossplane-preview-platform` and its GHCR app and Function packages are public. The evaluator-owned `YASHMAHAKAL/preview-gitops` repository is private. Argo CD has read-only repository access through a deploy key; the key is not committed. The local evaluator checkout uses the operator's Git credentials to publish trusted output. Synthetic downstream runs used PR numbers 4243 and 4244. Later, [real PRs #1–#8](live-pr-verification.md) proved GitHub artifact verification, watcher decisions, GitOps publishing, preview readiness, update/replay, rejection, and close cleanup. PRs #3, #4, and #5 were created through Backstage UI, an HTTP MCP client, and codex3 CLI respectively; PR #6 was created and updated through codex3 CLI. PR #7 was created directly to submit an unsupported resource; Backstage and codex3 read its rejection through MCP. PR #8 was created through Backstage UI with the `incident-policy` capability and selected vCluster mode.

For the vCluster run, the operator applied [the fixed namespaced installer Role](../deploy/local/vcluster-helm-installer.yaml) after Crossplane created the preview namespace. The provider could install and delete the chart in that namespace, while an authorization check denied it access in `default`. This per-preview bootstrap remains manual. Crossplane was not granted cluster-wide Role/RoleBinding creation or privilege escalation. A fully automated vCluster request path must preserve that boundary and still needs design and verification.

All seven approved PR close paths removed their GitOps preview directory, Application, XR, host namespace, and route. The rejected PR #7 never created those resources and remained empty after close. Both vCluster runs removed their Helm Release and persistent volume; the namespaced Role, PVC, and temporary secrets disappeared with each namespace. The temporary direct `pulseboard-smoke` deployment was also removed. The fixed CRD was absent from the host API during both vCluster runs. Backstage UI, HTTP MCP, and direct codex3 CLI requests work. On PR #6 update, the old XR and route were deliberately removed while new-head CI was pending, then recreated with the same PR URL, a new digest, and medium resources. PR #7 showed `unsupported-cluster-resource` through status API, Backstage MCP, and codex3 MCP with no URL. PR #8 proved the Backstage UI vCluster path and incident create/update through its live route. The status API currently reports `cleaning` without confirming final deletion; a merged PR is still unverified.

The local environment has `kubectl`, Helm, and Docker. The earlier `agent-guard` and `incidentpilot` kind clusters were deleted at the operator's request; Minikube was stopped and retained. The official Crossplane CLI v2.4.1 Linux amd64 download did not match its published SHA256 in this environment, so it was not executed; the v2.5.0 bundle checksum matched and was used.
